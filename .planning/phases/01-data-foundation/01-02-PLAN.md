Create src/scraper/client.py — TelegramClient class:
- __init__: takes Settings (or rate_limit_per_sec, user_agent), creates httpx.AsyncClient
- async fetch_page(channel_username: str, before: int | None = None) -> tuple[str, int]:
  - Build URL: https://t.me/s/{channel_username}?before={before} (before only if not None)
  - Rate limit: asyncio.sleep(1/rate_limit_per_sec) before request
  - Set User-Agent header from config
  - On HTTP 429: exponential backoff (1s, 2s, 4s, 8s, 16s, max 30s) with jitter (±20%), max 5 retries
  - On HTTP 200: return (html_text, 200)
  - On HTTP 404: raise ChannelNotFoundError(channel_username)
  - On other errors: raise with status code
  - Use httpx timeout (30s connect, 60s read)
- async close(): close httpx client
- async __aenter__/__aexit__ for context manager usage

Create src/scraper/service.py — ScraperService class:
- __init__: takes TelegramClient
- async scrape_channel(channel_username: str, max_posts: int = 20) -> list[ParsedPost]:
  - Fetch first page via client.fetch_page(channel_username)
  - Parse page via parser.parse_page(html)
  - Continue fetching if pagination exists AND posts collected < max_posts (CONTEXT: for now we only scrape first 20 posts per decision)
  - Return list of ParsedPost
  - On ChannelNotFoundError: return empty list + log warning
  - On rate limit exhaustion: return what we have so far + log error

The service does NOT interact with the database — it returns ParsedPost objects. The repository layer in Plan 03 handles storage and deduplication.
