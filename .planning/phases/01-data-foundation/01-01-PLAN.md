Create src/models/base.py:
- Async DeclarativeBase with MappedAsDatacolumn mixin
- Common columns: id (Integer, primary key, autoincrement), created_at, updated_at (server_default=now())
- Naming convention for constraints: "ix_%(column_0_label)s", "uq_%(table_name)s_%(column_0_name)s", "fk_%(table_name)s_%(referred_table_name)s_%(column_0_name)s"

Create src/models/channel.py — Channel model:
- id: Integer primary key
- telegram_id: BigInteger, unique, not null (numeric channel ID, survives username changes)
- username: String(255), nullable (username can change)
- name: String(500), nullable (display name)
- status: Enum('active', 'error', 'paused'), default 'active'
- last_scraped: DateTime, nullable
- last_error: Text, nullable (last error message if status='error')
- created_at, updated_at from base
- Index on telegram_id, index on status

Create src/models/post.py — Post model:
- id: Integer primary key
- post_id: BigInteger, not null (numeric ID from data-post attribute)
- channel_id: ForeignKey to channels.id, not null
- content: Text, not null (markdown, unlimited)
- datetime: DateTime(timezone=True), not null
- views: Integer, nullable (parsed from "1.5K" format)
- reactions: JSONB, nullable ({"emoji": count})
- link_preview: JSONB, nullable ({"title", "site_name", "description", "url"})
- author: String(500), nullable
- UniqueConstraint('channel_id', 'post_id') — this is the deduplication key
- Index on channel_id, index on datetime, index on (channel_id, post_id)
- relationship back to Channel

Create alembic.ini pointing to src.models.base metadata.
Create alembic/env.py configured for async migrations (using async engine from settings).
Generate initial migration: `alembic revision --autogenerate -m "initial schema"` — this creates channels and posts tables.

Create src/models/__init__.py exporting all models and Base.
